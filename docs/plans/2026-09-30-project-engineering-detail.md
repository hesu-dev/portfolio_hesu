# Project engineering detail implementation plan

**Goal:** 프로젝트 상세에서 핵심 기술, 기술 선택의 이유, 문제 해결 과정을 읽고 실제 구성 요소와 데이터 흐름을 아이콘 기반 아키텍처로 확인한다.

**Architecture:** 기존 Safari 상세와 프로젝트 데이터 모델을 확장한다. 문자열 노드 목록은 Finder·인쇄 호환성을 위해 유지하고, 상세 화면에는 좌표·아이콘·연결·경계가 명시된 다이어그램을 사용한다. Flutter 기본 그리기와 번들 아이콘으로 구현하며 의존성을 추가하지 않는다.

**Evidence:** 저장소의 기존 기록과 관련 로컬 원본 프로젝트를 읽어 구현 근거를 확인한다. PersonaChat은 설계로 표시하고, 근거가 부족한 회사 프로젝트는 확인된 구성 요소만 표시한다. 장애 사례, 측정값, 서버 연결을 추정해서 만들지 않는다.

1. 상세 화면의 기술 설명·의사결정·다이어그램 표시 요구를 위젯 테스트에 추가하고 실패를 확인한다.
2. 원본 코드와 문서에서 기술 선택 및 트러블슈팅 근거를 모아 프로젝트별 설명과 출처 문서를 작성한다.
3. 아이콘 노드, 방향 화살표, 연결 라벨, 경계선을 그리는 공유 위젯을 만들고 확대·닫기·작은 화면을 검증한다.
4. Safari 상세의 기존 텍스트 카드 구조를 다이어그램으로 교체하고 핵심 기술 → 의사결정 → 구조 → 기여 → 문제 해결 순서로 배치한다.
5. 관련 데이터·상세·탐색 테스트와 정적 분석, 웹 빌드를 실행하고 로컬 데스크톱·모바일에서 확인한다.

이번 요청에는 커밋·푸시가 포함되지 않는다. 앞선 Safari 시작 페이지 변경은 유지한다.
