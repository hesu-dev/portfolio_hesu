# 터미널 타이포그래피와 줄별 등장 모션 설계

## 목표

터미널 본문 안의 프롬프트, 입력값, 실행한 명령, 도움말 명령·설명, 일반 출력을 하나의 타이포그래피 규칙으로 통일한다. 색상은 명령·프롬프트와 일반 출력의 의미 구분을 위해 현재 역할별 색을 유지한다. 여러 줄로 이루어진 초기 도움말과 명령 실행 결과는 한꺼번에 보이지 않고 한 줄씩 아래에서 위로 떠오르며 나타난다.

## 설계

`TerminalApp`의 모든 텍스트는 `_terminalTextStyle`만 사용한다. compact 여부에 따른 크기는 기존 출력 기준인 `12.5 / 13.5`를 유지하고, 폰트는 `monospace`, fallback은 `Menlo`와 `Consolas`, 굵기는 `FontWeight.w400`, 줄 높이는 `1.45`로 고정한다. 도움말 명령의 굵은 글씨와 입력 프롬프트의 별도 스타일은 제거한다.

각 transcript 행 전체를 전용 reveal 위젯으로 감싼다. 행 하나는 500ms 동안 opacity 0→1과 세로 offset 양수→0을 `easeOutCubic`으로 함께 진행한다. 같은 출력 묶음에서 다음 행은 앞 행의 500ms 모션이 끝난 뒤 300ms를 쉬고 시작하므로 시작 간격은 800ms다. 초기 `help`도 하나의 묶음이며, 명령 제출 때는 화면에 추가되는 명령 echo와 결과 행을 새 묶음으로 취급한다. 출력 행은 처음부터 레이아웃 공간을 차지하지만 입력 영역은 마지막 활성 행의 reveal 완료 전까지 위젯 트리에서 제외해 빈 높이도 만들지 않는다.

마지막 행의 실제 애니메이션 완료 콜백이 현재 묶음과 일치할 때만 입력 영역을 마운트한다. 그 다음 프레임에 입력 포커스를 복원하고 transcript 끝으로 스크롤하므로 입력이 출력보다 먼저 보이지 않는다. 모션 축소 설정에서는 출력과 입력을 즉시 완료 상태로 표시하며, 이후 설정이 바뀌어도 완료한 묶음을 다시 숨기거나 재생하지 않는다.

출력 reveal을 기다리고 싶지 않은 사용자는 터미널 화면을 한 번 클릭하거나 터치해 현재 묶음을 즉시 완료할 수 있다. 터미널 전체의 pointer-down을 감지해 마우스와 터치에 같은 동작을 제공하고, 진행 중이면 모든 활성 행을 최종 상태로 바꾸면서 입력 영역을 표시한다. 이미 출력이 완료된 상태의 pointer-down은 기존처럼 입력 포커스만 복원한다.

## 검증

위젯 테스트는 모든 터미널 텍스트의 폰트·크기·굵기·줄 높이가 같고 색상만 달라질 수 있음을 확인한다. 모션 테스트는 첫 행의 500ms 진행, 300ms 휴지 구간, 다음 행 시작을 시간 단위로 검증한다. 입력 테스트는 마지막 행 완료 전에는 입력과 그 높이가 없고 완료 뒤에만 나타나는지, 모션 설정 변경 뒤에도 완료 상태가 유지되는지 확인한다. 별도 상호작용 테스트는 초기 출력의 터치와 명령 출력의 마우스 클릭이 각각 한 번에 모든 행과 입력을 완료하는지 검사한다. 이후 터미널 관련 테스트, 전체 정적 분석과 웹 빌드를 실행하고 로컬 web-server에서 실제 동작을 확인한다.
